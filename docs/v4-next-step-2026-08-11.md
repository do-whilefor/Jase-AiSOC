# AI-SOC V4.0 下一阶段推进记录（Migration 05）

## 本轮目标

上一轮最主要的 P1 blocker 是：生产链路虽然已 Rust First，但 PostgreSQL/SQLx migration 尚未落地，`Cargo.lock` 又仍停留在旧迁移基线。本轮不回退 Python，不机械翻译 Alembic，而是按照 V4 的 Rust storage boundary 建立原生 SQLx/PostgreSQL 平台能力，并把它接入部署、API readiness、release 与 CI。

## 已完成推进

### 1. 原生 PostgreSQL / SQLx migration plane

`aisoc-storage` 新增：

- SQLx 0.8.3 PostgreSQL runtime 依赖；
- `postgres.rs`：`PgPool`、连接超时、healthcheck、embedded migrator；
- `aisoc-db`：独立 Rust binary，支持 `migrate` / `health`；
- 3 个 forward migration；
- 15 张 V4 central schema 基础表：tenant/host/agent/operator/audit、ingest/raw index/normalized/DLQ/watermark、detection/incident/evidence/claim。

SQL schema 使用 tenant-qualified primary/foreign key 约束关键关系，避免仅靠应用层过滤实现租户隔离。Raw body 不直接作为 PostgreSQL 长期对象存储，而是预留 `raw_ref` / `object_key` / SHA-256 索引，继续与 V4 的 Object Store 方向一致。

### 2. Legacy Alembic 数据库 fail-closed

SQLx migrator 在执行前检查 `alembic_version`。如果发现旧 Alembic schema、但尚未建立 SQLx migration baseline，则直接返回 `LegacySchemaDetected`，不自动覆盖或混合创建同名表。

这意味着：旧 Python/Alembic 数据库仍作为迁移资产保留，但正式 Rust migration 不会对既有 legacy 库执行危险的“原地碰运气升级”。后续需要单独的数据迁移/校验工具完成 old schema -> V4 schema cutover。

### 3. Production API 开始把 PostgreSQL 作为硬依赖

Rust `aisoc-api`：

- `ApiState::from_env()` 改为 async 初始化；
- production 环境缺少 `AISOC_DATABASE_URL` 时拒绝启动；
- 启动时检查 PostgreSQL；
- `/readyz` 同时检查 PostgreSQL 与 Ingest；
- DB 不健康返回 `database_not_ready`。

当前 API 的业务查询仍主要代理到 Rust Ingest，因此这一步是 P1 dependency/readiness 收敛，不等同于 central repository 已全部切换。

### 4. Deployment / release 完整接入 `aisoc-db`

已更新：

- `deploy/Dockerfile`：构建并打包 `aisoc-db`；
- Rust release：由 5 个 binary 扩为 6 个；
- release checksum/signature/upgrade/rollback 测试同步覆盖 `aisoc-db`；
- P1/P2 Compose：新增 PostgreSQL + `db-migrate`，migration 成功后才允许 Ingest 启动；
- Linux installer：production control/all role 必须提供 `AISOC_DATABASE_URL`，启动 systemd 服务前执行 release 中的 `aisoc-db migrate`；
- `Makefile`：`make migrate` / `make db-health` 已切到 Rust SQLx；Alembic 只保留 `make legacy-migrate`。

### 5. CI 增强

Rust 1.82 job 已增加：

- PostgreSQL service；
- SQLx migration static gate；
- `aisoc-db migrate`；
- `aisoc-db health`；
- Rust CycloneDX SBOM 生成与上传；
- `cargo-audit` 保留。

同时 `check-cargo-lock.sh` 不再只检查 Workspace package，还会检查根 `workspace.dependencies` 是否进入 committed lock，避免手工补 package stanza 后得到假绿。

### 6. Python 仅做迁移兼容，不重新成为生产依赖

根 `.env.example` 现在使用 Rust/SQLx 的标准 `postgresql://` DSN。旧 Python Settings 在 legacy/regression 模式下会把它进程内规范化为 `postgresql+asyncpg://`，避免为了迁移期测试维护第二套数据库环境变量。

对应配置单元测试新增 DSN normalization 回归测试。

### 7. P1 阶段文档纠偏

旧 `docs/phase-p1-plan.md` 仍写成“Python 核心平台与工程底座”，与 V4.0 Rust First 不一致。本轮已按计划书 P1 硬门禁重写为“Rust 平台与工程治理”，明确 Cargo CI、SQLx migration、API health、SBOM、签名、日志/错误以及 central storage cutover 的真实退出条件。
