# API 与契约版本策略

## REST

- 公共 REST 路径使用主版本前缀 `/api/v1`；同一主版本内只允许向后兼容添加。
- 破坏性字段删除、语义变化或权限变化必须进入新的主版本，并提供迁移和废弃窗口。
- 创建操作支持幂等键；列表使用稳定游标；错误统一包含 `code`、`message`、`trace_id` 和可选字段错误，不暴露堆栈。
- 租户身份来自认证上下文，不接受调用方通过 Query/Body 任意切换。

## 事件与消息

- `schema_version` 使用 `MAJOR.MINOR.PATCH`；P0 契约为 `0.1.0`，在进入 P2 前冻结首个兼容基线。
- 消费者必须拒绝不支持的主版本；同一主版本的未知可选字段通过明确的扩展容器处理。
- 原始事件不可迁移覆盖；标准化事件按目标版本重算并保存 lineage。
- 幂等建议键：`tenant_id + agent_id + boot_id + source_event_id/sequence`。迟到事件更新版本化结论，不能重放响应动作。

## Protobuf/gRPC

- 字段号永不复用；删除字段使用 `reserved`；新增字段保持可选和安全默认值。
- Agent 批次 ACK 必须明确 accepted sequence、逐事件错误和可选策略版本。
- 部分 ACK 不改变或裁剪原批次；Agent 使用相同 batch_id、事件集合和完整性摘要重试，
  只有完整 accepted sequence 且无逐事件错误时才能删除本地批次。
- 协议协商记录 Agent/服务/Schema 最低和最高支持版本，不以握手成功等同能力完整。

## 数据库与规则

- Alembic 迁移只前进，破坏性变更采用 expand/contract，并提供备份与回滚说明。
- 规则、Prompt、模型路由、数据集、策略和插件均为不可变版本；运行结果引用具体版本。

## 兼容性门禁

每次契约修改必须验证：旧生产者 -> 新消费者、新生产者 -> 旧消费者（在声明支持范围内）、重复/乱序/缺失字段、非法租户字段、历史数据重放以及降级行为。
