# AI-SOC V4.0 下一阶段推进记录（Migration 06）

日期：2026-08-11  
基线：`Jase-AiSOC_V4_Rust_Migration_05_p1_sqlx_platform.zip`  
依据：`AI-SOC_Rust_AI-Web-Guard_项目计划书_V4.0.docx`

## 本轮目标

V05 已建立原生 SQLx migration plane，但 PostgreSQL 尚未真正成为 Ingest/API 的 central authoritative repository，P3 也缺少正式 DLQ replay 控制。本轮因此优先关闭以下结构缺口：

1. Agent inventory / raw event / normalized event / Detection / Incident 进入 typed SQLx repository；
2. API production 查询从 Ingest 内存态切到 PostgreSQL；
3. 本地 journal -> PostgreSQL 幂等 backfill/repair；
4. Agent revoke/host binding fail-closed；
5. normalize DLQ lease/replay/crash recovery；
6. 把旧 P3 Python 文档收敛到 V4 Rust First 当前状态。

## 已完成推进

### 1. PostgreSQL central repository cutover（base profile）

新增 `crates/aisoc-storage/src/central.rs`，提供 typed `CentralStore`：

- Agent inventory；
- ingest batch + raw event index；
- normalized event；
- Detection；
- Incident + Detection membership；
- watermark；
- normalize DLQ；
- tenant-scoped read model/status。

新增 migration：

- `202608110004_central_repository_cutover.sql`；
- `202608110005_dlq_replay_control.sql`。

当前共 5 个 Rust SQLx forward migration、15 张 V4 central tables。

Ingest 的 batch/raw/pipeline central write 在一个 PostgreSQL transaction 内完成；同一幂等键出现不同内容时返回 `DataConflict`，不做 last-write-wins 覆盖。

### 2. API authority cutover

Rust API production 在配置 PostgreSQL 后：

- `/api/v1/agents` -> `CentralStore::list_agents`；
- `/api/v1/detections` -> `CentralStore::list_detections`；
- `/api/v1/incidents` -> `CentralStore::list_incidents`；
- system status 的 central counts 来自 PostgreSQL。

Ingest internal endpoint 仍用于 readiness/runtime telemetry 和 development fallback，但不再是 production 资源权威源。

### 3. Startup backfill 与 central repair

Rust Ingest 启动后会把已有：

- heartbeat inventory journal；
- accepted raw evidence journal；
- pipeline journal

幂等回填 PostgreSQL。

`PersistentIngest` 对本地已接受的重复 batch 重新返回确定性 evidence，因此“本地 fsync 成功、PostgreSQL transaction 失败”的窗口可以由客户端重试修复 central repository，不会因为本地幂等命中永久漏写。

### 4. Agent revoke / host binding

新增 `AgentRevoked` / `AgentBindingMismatch` storage error。

live heartbeat/event 在写入本地 journal 前先检查 central identity；事务内再次 `SELECT ... FOR UPDATE` 校验：

- 已存在的 Agent 不能静默从 Host A 换绑 Host B；
- `revoked` Agent 不能通过 heartbeat/event 自动恢复 online；
- live event 返回明确 403；
- historical backfill 可以导入旧 evidence，但不能恢复 revoked 状态，也不能改变既有 Host binding。

### 5. P3 DLQ lease/replay

`event_dlq` 增加：

- `state = pending|leased|resolved`；
- `lease_owner`；
- `lease_until`；
- `resolved_at`；
- claim index。

`CentralStore` 增加：

- `claim_normalize_dlq`；
- `release_normalize_dlq`；
- `resolve_normalize_dlq_claim`；
- `persist_pipeline_replay`。

claim 使用 `FOR UPDATE SKIP LOCKED`。本轮复核又修复两项 crash/idempotency 边界：

1. `leased` worker 崩溃后，lease 到期可以被其他 worker 重新 claim；
2. rejected historical backfill 使用 idempotent `ON CONFLICT ... DO NOTHING`，不会把 resolved DLQ 重新打开。

Ingest 新增内部控制端点：

`POST /internal/v1/replay/normalize-dlq`

调用方只能指定 tenant/limit，不能提交 replacement payload。Replay 必须从本地 immutable raw journal 找到原始 evidence；本地 pipeline 已处理但 central write 丢失时进入 `AlreadyProcessed` repair；仍 rejected、raw missing 或 central failure 时释放 lease 并退避。

### 6. Rust PostgreSQL integration test

新增 `crates/aisoc-storage/tests/central_repository.rs`，CI PostgreSQL 环境将覆盖：

`inventory -> identity binding -> batch/raw -> normalized -> detection -> incident -> idempotent replay -> DLQ claim/release -> expired lease reclaim -> resolve -> resolved-not-reopened -> watermark -> revoke -> historical backfill`

当前沙箱没有 PostgreSQL server/Cargo，因此测试代码已纳入 CI，但不能在本机伪报执行成功。
