# P0 安全不变量静态评审记录

评审范围：`aisoc-contracts`、JSON Schema 导出清单、Web/SOC/Control/Response Contract Test 源文件，以及七平面架构和威胁模型。

评审方式：在 Windows 无 Rust 环境下进行源码和文档静态审阅。未执行编译、测试、Schema 导出、服务运行、数据库或故障注入。本记录只证明安全不变量已经形成可审查的 Rust 契约和负向样本，不替代计划书要求的 Linux 动态验证。

时间关系守卫统一调用 `Timestamp::is_before` / `Timestamp::is_after`，使用 RFC3339 解析后的时间值比较；`Timestamp` 不实现 `Ord`，避免业务代码误用字符串字典序比较带不同时区偏移的时间。EvidencePackage 与 Claim 的 Evidence 时间闭包均允许同一时刻，只拒绝严格晚于容器/断言创建时间的采集记录。

Agent/Event 字段审计没有把运行时状态伪装为 P0 DTO 内部不变量：离线队列允许 `created_at` 早于后续连接的 `authenticated_at`；压缩比与原始消息大小、receive-time 时间漂移、batch 幂等和同键异 digest 需要 P3 Ingest 状态；证书 fingerprint 的注册/轮换/吊销 authority 需要 P2。上述项保持后续阶段动态守卫，不在 P0 对已解码 payload 作猜测。

## 静态评审结论

P0 的七项核心安全不变量已形成 Rust 权威契约、显式 decision enum 和负向测试源文件。custody 与 EvidenceRef 共用的完整性状态机还直接覆盖了 `Verified → Failed` 的后续篡改发现，以及 Failed 不可恢复。Audit/Error 及其 SchemaVersion/SafeFields 公共前置决策已经闭合直接结果样例；关键跨边界集合、文本、扩展对象与有效时间窗均已补充显式上限。未发现 Python/TypeScript 生产运行依赖、Windows 专属实现、任意 Shell/SQL/URL 执行器或关键 ID 退化为普通字符串。

P0 仍不能关闭：Schema 快照尚未由 Linux 锁定 toolchain 生成，四域 Contract Test 尚未执行，动态身份/对象/状态/解析/重放/故障变量尚未验证。正式阶段状态保持“代码已实现，待 Linux 编译和验证”。
