1. 执行摘要与项目目标
1.1 项目定位
本项目建设一个面向蓝队的通用 Linux 安全分析平台。系统通过端点 Agent、网络传感器和服务日志接入，采集网络连接、Web/SSH/数据库访问、进程、文件、账号、权限、持久化和资源使用等证据；由确定性规则、统计异常、行为链、恶意文件引擎和 AI Agent 联合完成告警研判、攻击链还原、技术溯源和受控响应。
平台采用“传感器产生事实、检测引擎发现异常、事件引擎聚合证据、确定性工具验证事实、AI 关联解释、策略引擎控制动作、固定执行器实施处置”的边界。大模型不是包过滤器、杀毒引擎或最终事实来源，也不得逐日志、逐网络包或逐 syscall 运行。所有高风险结论必须能追溯到 evidence_id、查询结果或恶意文件分析结果；动态样本执行必须位于独立沙箱信任域。
产品目标：形成可在多种 Linux 发行版部署的统一 Agent 和中心平台，能够真实识别异常访问与入侵后行为，并把“攻击尝试、攻击成功、主机失陷、恶意软件活动”分层表达。
1.2 建设目标
兼容主流 Debian、RHEL、SUSE、Arch 系 Linux，并将 Kali 纳入同一兼容体系。
识别网络扫描、Web 攻击、SSH 爆破、异常登录、提权、持久化、横向移动、C2、挖矿、木马和蠕虫传播等行为。
建立事件证据链、攻击时间线、实体关系图和影响范围分析能力。
支持 Kimi、GLM 及其他 OpenAI 兼容或自定义协议模型；模型数量不足时自动降级而不中断流水线。
通过 Claim-Evidence、工具查询、盲审和策略门控降低 AI 幻觉。
提供单机、中心化和高可用部署方式，并支持后续向容器、云和混合环境扩展。

1.4 工程落地原则
资源数量和建设周期不作为本项目的主要限制，但技术依赖、安全边界和可验证性仍必须严格串联。完整产品愿景可以并行建设，任何高级能力不得成为基础检测主链路的单点依赖。
先形成“采集—确定性检测—Incident 聚合—证据验证—研判—人工处置”的闭环，再扩展多模型、动态沙箱、跨事件图谱和高风险自动响应。
模型、全文检索、图数据库、沙箱和高可用组件均采用可插拔架构；关闭任一可选组件时，基础安全检测和证据留存仍可运行。
每个阶段以退出条件、攻击回放、性能基线和故障恢复结果判定，不以日历时间或代码完成度替代验收。
“支持发行版”必须绑定发行版版本、内核范围、能力等级和验证报告，不以安装成功等同于完整兼容。

2.3 明确边界
AI 可以进行技术溯源和攻击链还原，但不能仅凭 IP 确认攻击者真实身份。
未解密的 TLS 流量不能提供完整 HTTP 参数；需要反向代理、应用日志或服务端可观测数据。
单一高 CPU、端口 3333 或陌生文件名不能直接证明挖矿；必须结合进程、协议、文件和持久化证据。
模型不得生成任意 Shell 并自动执行；处置动作必须来自受控工具目录。
高风险动作默认人工审批，低风险动作才可在策略满足时自动执行。
2.4 非功能性目标与明确非目标
产品范围除功能清单外，还必须通过可靠性、性能、安全性、可解释性和可运维性约束。以下项目作为架构评审和验收的强制条件。

3. Linux 兼容性设计
3.1 兼容策略
兼容性不能通过在代码中硬编码 /var/log、systemctl、apt 或 yum 实现。Agent 启动时执行能力探测，根据内核、init、日志系统、包管理器、BTF、cgroup、LSM 和权限自动选择采集器；无法启用高级能力时，以可观测且可审计的方式降级。
启动 → 识别发行版/os-release → 探测内核与 BTF → 探测 systemd/journald/auditd     → 探测 eBPF hook 与权限 → 选择采集 profile → 上报 capability_report

4.4 控制面、数据面与证据面的分离

5. Python 工程架构与技术栈
5.1 语言与工程原则
服务端和 Agent 主体使用 Python 3.12+；中心服务采用异步 ASGI，Agent 采用事件循环与多进程 Worker。eBPF 探针仍需编译为 eBPF 字节码，可通过 BCC Python 绑定、签名后的 libbpf CO-RE 辅助程序或 Falco 接入，禁止用 Python 模拟内核探针。
核心事件、配置和接口模型通过 Pydantic/Protobuf 共享，禁止各服务重复定义 Schema；跨进程和跨服务边界使用版本化契约。
I/O 并发统一 asyncio，Linux 环境可启用 uvloop；CPU 密集型规则、压缩、哈希和文件分析进入独立进程池或专用 Worker，避免阻塞事件循环并降低 GIL 影响。
依赖统一由 pyproject.toml 与锁文件管理；原生扩展和预编译 wheel 必须按架构固定、签名和扫描。mTLS/密码学使用 Python ssl/cryptography，密钥仍由 Vault/KMS 管理。
每个外部组件通过 Protocol/ABC 和 Adapter 接入，业务代码不绑定厂商 API；动态导入、反序列化、subprocess 和 ctypes/cffi 必须隔离、白名单化并审计。

6.2 Agent 关键能力
本地磁盘队列：中心不可用时继续缓存，达到容量后按优先级丢弃并上报计数。
批处理与压缩：Protobuf + zstd，控制带宽和 CPU。
事件去重：source_event_id + boot_id + sequence，避免重启和重试重复。
策略热更新：采集范围、过滤、规则、采样、保留和动作权限均由签名策略控制。
自保护：Agent 制品、启动器和配置签名，依赖锁定与完整性校验，最小权限、systemd hardening、watchdog 和受控恢复模式。
时间质量：记录 event_time、ingest_time、boot_id、clock_offset，并监控 NTP 偏差。
6.3 eBPF 与降级方案
Agent 以 Python 管理采集器生命周期，eBPF 数据面采用三种可插拔路径：BCC Python 绑定加载受限 C 探针、调用签名后的 libbpf CO-RE 辅助程序读取 ring buffer，或直接消费 Falco/其他传感器输出。Python 进程不得在运行时接收模型或远端下发的任意 C/eBPF 源码。加载失败时不应导致 Agent 整体退出，应按进程→网络→文件等能力逐项降级到 Falco、auditd 或日志模式。

6.5 Agent 更新、制品与身份完整性
发布制品、策略包、规则包和 Collector 清单必须签名；Agent 在安装、启动和热更新前验证签名、版本、目标平台和哈希。

9.3 静态分析与动态沙箱的信任边界
恶意文件静态分析属于平台基础能力；动态执行属于独立高风险系统。中心服务和端点 Agent 不得直接加载、解释或执行待分析样本。

10.3 幻觉控制与审核边界
原子 Claim：每个结论只表达一个事实或推断，并包含 evidence_ids。
证据校验：引用不存在、时间不匹配或不支持结论的证据直接判为 invalid。
确定性工具优先：计数、登录结果、hash、进程树、网络会话由查询程序验证。
盲审：Verifier 不接收 Analyzer 的品牌、自信分和完整推理，减少锚定。
不确定性显式化：supported、partially_supported、insufficient、contradicted。
模型历史校准：按场景统计过度判断率、遗漏率和结构化输出成功率。
Prompt Injection 防护：日志与指令分离，原始字段永远视为不可信数据。

14.3 安全控制
Agent 和中心使用双向 TLS，证书可轮换和吊销。
密钥进入 Vault/KMS 或加密配置，不写入日志。
RBAC/ABAC 控制租户、资产组、证据和动作权限。
所有 AI 输入做字段级脱敏；不可信日志不得进入系统指令。
恶意样本存储禁止执行权限，下载需审计和短期授权。
响应工具使用目标重验证，防止 PID 复用、路径替换和竞态。
审计日志记录模型、Prompt 版本、工具参数、审批人、执行前后状态。
14.4 分级响应阶梯与执行门禁
所有写入动作先执行 dry-run/plan，输出目标、影响范围、命令模板、回滚和证据，再进入审批。
同一 Incident 的动作数量、目标数量和并发度受执行预算限制，防止错误结论扩大影响。
Action Runner 只接收结构化动作 ID 和固定参数，不接收任意 Shell 文本。

17.4 数据集治理与可重复评测
每个场景数据集包含正常、失败攻击、成功攻击、弱信号、数据缺失、时钟偏差、乱序和重复事件，并记录来源、生成脚本、许可和版本。

评测报告同时给出总体指标和按发行版、Profile、数据源、资产关键度、攻击阶段的分层结果。
每次规则、Schema、Collector、模型或 Prompt 变更触发受影响数据集回放，并保存差异、性能和误报变化。
攻击仿真只在隔离授权环境执行；真实恶意样本使用安全替代或隔离沙箱，禁止在生产 Agent 直接运行。

20. 最终验收标准
类别
Go 标准
兼容性
覆盖目标发行版代表版本；基础模式全部通过，完整能力按 Profile 和支持等级标注，安装成功不得替代能力验证。
检测
网络/Web/认证/主机/恶意文件核心场景达到第 17 章指标，攻击尝试、疑似成功和确认失陷能够区分。
证据
所有确认失陷结论具备可访问 evidence_id；不存在引用、跨租户引用和伪造查询结果为 0。
事件质量
断网、重放、迟到、时钟偏差和重复事件处理通过；不存在不可解释数据丢失或重复响应。
AI 门控
原始日志不直接调用模型；仅通过 AI Review Gate 的 Incident 创建 AIReviewTask；聚合、采样、预算和降级可审计。
AI
至少两种 Provider 和本地/不可用降级流程可运行；确定性工具结果优先于模型，多模型一致不作为事实证明。
幻觉与注入
逐 Claim 验证、盲审、冲突升级、Prompt 注入和恶意工具参数测试通过；未授权工具调用为 0。
数据出域
数据分级、租户策略、字段最小化、外部 Provider 限制和模型输入输出保留策略通过审计。
溯源
能还原入口、主机内行为、横向路径和影响范围；归因限制明确，迟到证据可触发版本化修订。
恶意软件
YARA-X/ClamAV/上下文关联可用，样本存储隔离；动态沙箱如启用则独立信任域并通过逃逸和外联测试。
响应
R0-R3 响应阶梯、审批、审计、目标重验证、执行预算和回滚可用；关键资产无未审批 R3 动作。
供应链
Agent、服务、策略、规则和插件制品签名，SBOM、漏洞扫描、灰度升级、防降级和证书吊销完整。
工程
升级回滚、备份恢复、容量告警、故障演练、监控和运维手册完整；可选组件故障不阻断基础检测。
性能
Agent 各 Profile 资源、中心吞吐、积压恢复、检索和 API 满足容量报告；压测可重复。
Go/No-Go
真实攻击回放不稳定、正常日志大规模触发 AI、确认失陷存在无证据 Claim、样本越界执行或高风险动作不可控时，不得进入生产。

Go/No-Go 原则：如果真实攻击回放无法稳定复现、正常日志仍会大规模触发模型、确认失陷结论仍存在无证据 Claim、或者响应动作无法受控回滚，则不得进入生产试点。
